需要实现整体新的数据标注流程，可以参考当前 web/annotations 的已有功能基础：
1. 数据与标签导入（与当前一致，后续需要拓展不同的标签导入能力）
2. 第一轮筛选（粗筛）：需要评价MOS分、以及是否有瑕疵，问题由创建人录入（可能有多个，但是一个为主）
3. 第二轮筛选（精筛）：对第一轮符合条件的图片（例如MOS > 3，且无问题）进行第二轮MOS分、以及是否有瑕疵（可选）进行打分
4. 基于数据分布进行数据采样
5. 符合打标标签，纠正错误标签（需要标注的标签在创建任务时选定）

性能约束：

- 首页任务列表应读取任务元信息和 `summary.json` 快照，最新进度通过 `/api/tasks/<task_id>/summary` 异步刷新。
- 标注页应直接加载 `/api/tasks/<task_id>` 和当前阶段分页数据，不应先等待全部任务列表。
- 阶段分页接口即使 `limit=1`，也只能为返回页构造完整 payload。
- 图片接口应优先返回预热缓存中的 1024 预览图；缓存未命中时不应同步缩放，应先返回原图并通过响应头标记 miss。
- 后端应保留 summary、阶段分页和图片缓存查找的分段耗时日志，方便远程部署定位瓶颈。
